## Proposal Report

### 動機與目標
#### 動機
大概是昨天我又發現自己忘記寫 WebWork 的微積分作業了。雖然那份作業占的分數不高，但看到自己就這樣白白錯過，心裡還是很痛。也因為這件事，我開始認真覺得自己需要一個專門拿來提醒 deadline 的系統。

現在常見的日曆 app 對我來說比較像是拿來記錄大事件，例如考試、活動、開會或重要行程，但如果把作業、報告、測驗、申請期限這些東西全部混在一起，我會覺得畫面很亂，反而更難注意到真正快到期的小任務。再加上 NTU COOL 上的通知很多，有時候會夾雜各種公告、課程資訊和作業提醒，資訊太雜的情況下，反而容易漏掉真正重要的 deadline。

因此，我想自己做一個「作業截止日管理系統」，把重點放在 deadline 的管理與排序上，讓我可以更清楚看到最近要到期的任務，而不是被一堆雜訊干擾。這個系統希望能做到新增、刪除、修改與查詢任務，並且依照截止時間自動排序，幫助使用者更有效率地掌握近期要完成的事情。


#### 目標
1. 建立一個可新增、刪除、查詢與修改任務的截止日管理系統。
2. 使用紅黑樹作為核心資料結構，維持任務的有序排列。
3. 提供依照 deadline 顯示所有任務與查詢最近到期任務的功能。
4. 說明此系統與資料結構、進階程式設計及 Linux kernel 設計概念之間的關聯。


### 預期功能
1. **新增任務**
   - 使用者可輸入任務名稱、課程名稱、deadline、優先級與備註。
   - 系統會將任務插入紅黑樹中，依 deadline 維持排序。

2. **刪除任務**
   - 使用者可刪除已完成或不需要的任務。
   - 系統需正確更新紅黑樹結構。

3. **修改任務**
   - 可修改任務內容，尤其是 deadline。
   - 若 deadline 改變，需重新維持資料的有序性。

4. **查詢最近到期任務**
   - 可快速顯示目前最接近截止時間的任務。

5. **列出所有任務**
   - 依 deadline 由近到遠顯示所有任務。

6. **標記完成狀態**
   - 可將任務標記為已完成或未完成。

7. **進階功能（若時間允許）**
   - 任務分類（作業、考試、報告、生活提醒）
   - 搜尋特定課程或關鍵字
   - 匯出任務資料到文字檔案
   - 比較自平衡二元樹與其他資料結構在此情境下的效率差異

8. **效能比較**
   - 比較 Red-Black Tree、普通陣列與排序陣列在 deadline 管理上的效率。
   - 預計比較新增任務、查詢最近 deadline、列出所有任務等操作。
   - 記錄操作時間，並整理成輸出結果。

### Prototype 預計可驗證內容

Prototype 階段預計完成一個可以在終端機操作的基本版本，重點是先驗證核心資料結構與 deadline 管理流程是否可行。

預計可驗證的內容包含：

1. **任務資料格式是否能正常建立**
   - 可以建立任務名稱、課程名稱、deadline、優先級與備註。
   - 可以正確顯示任務內容。
   - 可以標記任務是否完成。

2. **Red-Black Tree 基本操作是否正常**
   - 可以插入任務。
   - 插入後能維持依 deadline 排序。
   - 可以透過 in-order traversal 依 deadline 由近到遠輸出任務。

3. **最近到期任務查詢是否可行**
   - 可以找到目前 deadline 最早的任務。
   - 新增任務後，最近到期任務可以正確更新。
   - 若任務被刪除，也可以重新整理資料並找到下一個最近到期任務。

4. **基本任務管理功能是否完成**
   - 新增任務。
   - 刪除任務。
   - 修改任務。
   - 查詢最近到期任務。
   - 列出所有任務。

5. **初步效能比較是否可執行**
   - 使用相同任務資料，比較普通陣列、排序陣列與 Red-Black Tree。
   - 測試新增任務所需時間。
   - 測試查詢最近 deadline 所需時間。
   - 初步觀察不同資料結構在 deadline 管理情境下的差異。

Prototype 階段不一定完成完整 UI，但會先完成核心功能，也就是 Red-Black Tree 的任務管理與初步效能比較。Final 階段再補上更完整的測試資料、效能分析與使用介面優化。

### 競品比較

| 項目 | Google Calendar / Apple Calendar | NTU COOL / 課程平台通知 | 一般 To-do List App | 本專題：作業忘記寫了 |
|------|----------------------------------|--------------------------|----------------------|------------------------|
| 主要用途 | 管理行程、活動與會議 | 課程公告、教材與作業通知 | 管理待辦事項 | 專注管理作業與 deadline |
| Deadline 排序 | 可以，但通常需要手動整理 | 資訊較分散 | 通常可以 | 以 deadline 為核心自動排序 |
| 最近到期任務查詢 | 不一定直覺 | 容易被公告淹沒 | 視 app 而定 | 可直接查詢最近到期任務 |
| 是否能展示資料結構效能 | 否 | 否 | 否 | 可以比較不同資料結構效率 |
| 是否適合學生作業情境 | 普通 | 是，但通知較雜 | 普通 | 專門針對學生 deadline 設計 |

和一般日曆 app 相比，本專題不會把重點放在完整月曆或行程視覺化，而是專注於「有哪些任務快到期」。這樣可以降低資訊干擾，讓使用者更快看到真正需要處理的作業、報告或測驗。

和課程平台通知相比，本專題的資訊更集中。課程平台通常會混合公告、教材、討論區與作業通知，容易造成資訊過載。本系統則只管理使用者主動加入的任務，並依照 deadline 排序。

和一般 To-do List App 相比，本專題除了基本任務管理外，也會實作底層資料結構，並比較 Red-Black Tree、普通陣列與排序陣列在 deadline 管理上的效率差異。
